## Decisions
1. **Units.** The report's HH table assumes a 3.25-heads hero; the real Cast v2 Hero kid is 4.33 of his own heads (0.96 BU head, 4.16 BU). I kept the report's height ratios to the hero (1 HH = 1.28 BU) and its head multipliers (0.82-1.05x the hero head), so on-screen contrasts match the report (Oathbound 2.0x, Jailer 1.53x, First Rank 1.46x, Ember 1.0 HH / 3.25 HH) and faces stay readable; head-share percentages therefore come out lower than the report's (e.g. First Rank 16 % not 21 %). Widths use W = 0.96 BU; "shoulders" = torso-top width, arms sit outside it (Roblox R15 style).
2. **Kit.** `v3kit.py`: 12 body-type records -> lofted superellipse parts (soft-edged blocks like Cast v2), 16 R15-named bones built from the same numbers, rigid bone parenting (no weights to break), `_Att` socket empties. Poses are direction targets solved into quaternions, stored as JSON on the rig and as Action assets. Faces: one material per head, integer `face` / `mouth` / `blink` and float `glow` read through Attribute(Object) nodes, driven from the rig (verified: drivers retarget after Append, packed images travel with the collection).
3. **"kneel-free"** read as "the pose set has no kneel" (the report's kneel fatigue). The legs can still be posed into a kneel by hand.
4. **Face styles per table:** visor slit and hood glow (new, no face), sharp rival set (new, shared by First Rank and the Rigger with different iris colours and eye shapes), Hero kid's set + 2 new + glow overlay (True-Form), creature storybook-family set (new, Ember), toybox family + 4 new + talk set (Squire: the "classic simple decal family, pushed expressive"; kept off classic-block so the Squire doesn't share a face style with the two yellow crowd members), storybook with recoloured irises (4 crowd) and classic-block (2 yellow crowd); crowd "neutral" = the pack's happy eyes + determined's flat mouth. No blush, no big glossy puppet eyes (anime-shine not used).
5. **Squire vs Goofy guard**: both classic yellow with a pot helmet. Made the Squire's a brass *saucepan* with a long handle sticking out sideways, a lanky R15 body, teal tunic and a mountain backpack so the two never read alike.

## Render budget
2 CPU cores and one memory cgroup shared with other agents (load average ~7). Renders ran at roughly a third of normal speed (the first 3600x1300 lineup took 14.5 min). Sheets use 1500-1800 px strips at 10 samples + OpenImageDenoise, faces at 230 px per head; these peak under ~1 GB. The full lineup scene peaks at ~0.9 GB at thumbnail size but **~2.5 GB at 2800x820**; two 3000-3600 px attempts were OOM-killed by the shared limit, so the final lineup is 2800x820 / 14 samples. Coordinator rule from 16:10: only one render at a time, at nice 19, under ~1.5 GB; for phase 2, render lineups at about 2000x600 or in halves. Every PNG was viewed before hand-off.

## Not done / limits
- glb backups carry plain colours (the procedural weave/leather/metal and the face-switch shader don't exist in glTF); the default expression is baked to a texture, all expression PNGs and pose JSONs sit next to the glbs. The .blend is the real deliverable.
- Rigs are rigid FK for stills (no IK, no weights); fine for Roblox-style posing, not for cloth sim. Capes and coat tails follow the torso only, so extreme leg poses can clip them.
- Pose Library actions live in cast-v3.blend; an appended collection brings the poses as the rig's JSON property (use `cast_v3_tools.set_pose`), not as Actions.

# Cast v3 phase 2 build log (Claude, Thu 11-27 evening): report rows 9-20

## Method (same kit, same tools)
- Same files, extended: `cast_v3.py` (phase-2 builders + data records after the phase-1 ones), `v3kit.py` (new `block` head kind only), `faces_v3.py` (phase-2 decals: `FACES_PHASE=2 python3 -I faces_v3.py`), `render_v3.py`, `meta_v3.py`, `compose_sheets.py`, `export_glb.py`, `cast_v3_tools.py`. Phase-1 copies of the edited scripts are in `scratch/p2/*.phase1.bak.py`.
- **Append mode**: `BASE=cast-v3.blend ONLY=<key> SAVE=... python3 -I cast_v3.py` opens the library, removes any old copy of that character (objects, meshes, pose actions, unused materials and face images), reuses the shared `CV3 ...` materials, builds, and places it after the others. Each character was built into `scratch/p2/work.blend`, checked, then copied over `cast-v3.blend` (compressed, textures packed), so a restart loses at most one character.
- **Hand props**: modelled where they belong in the character's default pose, then moved into the hand bone's rest space (`to_rest`), so they sit exactly in the hand in that pose and follow it in every other pose. A small two-bone IK (`ik_arm`) puts a hand on a target (the Herald's trumpet). `solve_twist` turns a hand so a prop points the right way in another pose (the Old Legend's raised sword).
- **Switchable props**: rig integer properties drive visibility or glow colour (Old Legend `sword`, Roll Merchant `rarity`, Stone Keeper `class`, Jester `puppet`). `rig['pose_props']` lets `set_pose` set them with a pose.
- **Budget**: every Blender job through `p2run.py` (waits for 2.5 GB available, nice 19, stops only its own child above 1.5 GB, logs peak RSS to `scratch/p2run.log`). OIDN's default ACCURATE prefilter alone took ~600 MB; `render_v3.py` now defaults to the FAST prefilter (~450 MB). Sheet renders peak 0.5-1.17 GB.
